# 前端效能檢測與打包優化（2026-10-02）

## 怎麼量的
- 正式版建置（`vite build`）用 `vite preview` 開，Playwright 的 Chromium 量。每個情境冷載入 3 次取中位數。
- 桌機：1440×900、DPR 1。手機：390×844、DPR 3、觸控、CPU 降速 4 倍。慢速網路：RTT 150 ms、下載 1.6 Mbps。
- 限制：沙箱沒有 GPU（WebGL 用軟體算），地圖的 FPS 與 idle 時間比實機慢很多，只拿來比前後。OpenFreeMap、Wikimedia 照片連不到，地圖只畫縣界、照片不計流量。Google Fonts 先錄一次再從本機重放。
- 腳本、原始數據、trace 在當次工作的暫存資料夾，沒有放進 repo。

| 收集冊 240 張卡的合成圖層（手機） | 1,698 | 30 |

## 做了什麼
- **收集冊**：卡片靜止時畫成平面（沒有 3D、背面、反光、箔片層），滑過、聚焦或打開才變回立體。畫面外的卡不畫（`content-visibility`），發牌動畫只播第一屏。
- **Firestore 延後**：`services/firebase.ts` 只管登入；Firestore 改在 `services/firestoreDb.ts`，登入後才載。登入用的 popup resolver 只在按「登入」時帶入，開頁面不再先載 `apis.google.com` 的 gapi script。
- **地圖引擎自成一檔**：`vite.config.ts` 的 `codeSplitting.groups` 把 maplibre-gl 拆出去。改版時回訪的人只重抓 app 那一份（約 100 KB），地圖引擎走快取。
- **首頁不載地區特色**：探索頁只載航線（地區標籤用），地區特色、季節、會話載過就不重抓。
- **資料檔帶版本**：地區特色、季節、會話、航線的網址加上 `?v=`（`_index.json` 的 `extras`），service worker 存過就不再背景重抓。
- **資料索引提早抓**：`index.html` 加 `<link rel="preload" as="fetch">` 抓 `_index.json`，並先連 `tiles.openfreemap.org`、`upload.wikimedia.org`。
- **service worker 延後註冊**：開場畫面拿掉、瀏覽器空下來之後才註冊，預先快取（約 2.7 MB）不和首次載入搶頻寬。
- **手機不畫看不到的清單**：探索頁左側清單在手機用 `v-if`，不再 `display:none` 藏著。
- **開場畫面期間的地圖定位不播動畫**：直接開 `/map/:pref` 時省掉 0.9 秒的 fitBounds 動畫。
- **選景點只重送一次地圖資料**：原本景點清單與選取各觸發一次全量 `setData`。
- **衣櫃**：捲動窗外的單品先不畫。

## 成就系統合併後再做
這三項會改到成就系統也在改的檔案（`DollWalker`、`CardReveal`、`UserMenu`），等成就合併後做：
- 旅人相關元件與 157 件服裝的 SVG 延後載入，沒登入就不下載（入口約 −30 KB gzip，估計）。
- 景點面板與新卡入手畫面延後載入，選景點時才載（約 −15 KB gzip，估計）。
- 沒登入時不掛散步的旅人。

## 評估後不做
- **其他頁面不下載地圖引擎**：首頁本身就是地圖頁，延後載入反而會讓首頁慢半拍；直接打開 `/log`、`/trips` 才省得到。
- **離開地圖再回來時保留地圖**：牽涉很多監聽器的生命週期，容易留下過期狀態。

## 要你決定
- **字型**：開頁面時最大的負擔。Google Fonts 的 CSS 有 705 個 `@font-face`（195 KB gzip），首頁要抓 41–42 個 woff2（約 1.4 MB），京都地圖頁桌機抓到 91 個（約 3.4 MB）。擋掉網路字型量到的差別：

| 情境 | 有網路字型 | 只用系統字 |
|---|---|---|
| 手機首頁版面計算 | 3.13 秒 | 0.40 秒 |
| 手機首頁開場畫面消失 | 9.2 秒 | 7.0 秒 |
| 手機 `/map/kyoto` 開場畫面消失 | 9.3 秒 | 6.8 秒 |
| 桌機首頁開場畫面消失 | 4.6 秒 | 3.7 秒 |

  - 做法一：內文改系統字（PingFang TC、Hiragino Sans、Noto Sans CJK、Microsoft JhengHei），網路字型只留標題與拉丁字。整站字體外觀會變。
  - 做法二：只拿掉 900 字重與重複的日文字族，量到的版面計算約 1.78 秒，大概省一半。
- **開場畫面的尾巴**：最後一項載完之後，開場畫面還會再跑約 2 秒（補點、停一下、1.1 秒退場）。可以縮短退場。

## 之後可以做（pipeline）
- 擴充包（4 個，66 KB gzip）在打開擴充包或選景點時才載；各縣件數放進 `_index.json`。
- 景點詳細資料（京都 849 KB）切成小檔，第一次打開景點從約 158 KB gzip 降到 10–20 KB（估計）。
- 搜尋索引（1.8 MB、596 KB gzip）依字首切檔或拿掉重複欄位。
- 年代主題的 CSS（約 14 KB gzip）跟年代字型一起，選了才載。
