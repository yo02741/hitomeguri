# ひとめぐり 手機版面計畫

2026-10-03。「手機版先不做」解除後的第一份計畫。依據六組實測：探索、深度探索、行程、紀錄、收集、外框。實測尺寸為 390×844、360×740、橫向 844×390／667×375，平板 768–1023。（實測截圖留在當次工作的暫存資料夾，沒有放進 repo。）重複的項目已合併。以下三類已拿掉：
- 和使用者今天的回饋衝突的：散步的旅人與「立體」在手機隱藏；縮放鈕維持 MapLibre 預設大小；縣地圖清單在上方 40dvh，開 sheet 時收起。
- 違反 PLAN §6a 文案規則的。
- 實機才能確認的，改列成「實機確認」。

## 1. 現況總結

- 手機版目前「開得起來、不會壞」：13 個路由在各尺寸都沒有水平捲動，安全區、16px 輸入框、手機搜尋都做對了。滑卡、蓋章、扭蛋、成就的捲動與動畫在直向都正常。
- 主要問題是「到不了」和「看不到」：
  - 到不了：深度探索、擴充包、只看收藏、期間限定、直飛航線在 1024 以下沒有入口。擴充包在手機上還可能被打開卻關不掉。
  - 看不到：選取的景點和祭典的釘落在 sheet 或清單底下；sheet 的收藏、去過要先捲 400px 以上；橫向時卡片檢視、開卡包、帳號選單的按鈕掉出畫面外。
- 外框有幾個全站問題：換頁時捲動位置會帶到下一頁（已重測確認：/log/cards 捲到 1500 後點「紀錄」，/log 一打開就在 1500）、返回手勢不會先關浮層、點選單外面會連帶點到底下、鍵盤出現時分頁列蓋住輸入框。
- 效能大致可以：4x 降速時捲動都順。慢的有四處：類型篩選切回「不限」2.9–3.9 秒、收集冊篩選 835ms、關 sheet 時重建清單 1.1 秒、冷啟動 2.7–3.9 秒（dev）。
- 旅途中最常用的行程頁還沒照 UX-FLOW 的手機版面做：不會停在今天、第一個停留點在第一屏以外、離線不能改而且看不到失敗。

## 2. 第一階段（必要：功能到得了、不壞、不擋）

### 外框

1. **換頁時捲動歸零，返回時還原**
   - 位置：`App.vue`（共用的 `<main>`）、`router/index.ts`。
   - 原因：全站共用一個捲動容器，router 也沒有處理捲動。重測：/log/cards 在 1500 時點「紀錄」，/log 一打開就在 1500，只看得到清單尾端（`synth/carry-log.png`）。旅前準備（約 16,000px）返回後也找不到原段落。
   - 做法：`afterEach` 在 push 時歸零。popstate 時用 `history.state.position` 還原先前存下的位置。有 #hash 的照舊交給 scrollSpy。深度探索頁用自己的內層捲動，不在這一項處理，見第二階段。
   - 工作量：S
2. **帳號選單在橫向放不下，「年代」與「登出」點不到**
   - 位置：`UserMenu.vue`、html/body overflow。
   - 原因：844×390 時選單 423px 高；滑動時捲動的是整頁，header 和分頁列跟著跑掉。
   - 做法：
     - 選單加 `max-h-[calc(100dvh-var(--spacing-header)-1rem)] overflow-y-auto overscroll-contain`。
     - html 與 body 設 `overflow: hidden`，`#app-root` 本來就是 h-dvh。
     - 768 以下從選單拿掉「我的行程」「旅行紀錄」，分頁列已經有這兩項。
   - 工作量：S
3. **點選單外面會連帶點到底下的東西**
   - 位置：`UserMenu.vue` onPointerDown。
   - 原因：實測選單開著時點「東北」列，選單關了，東北也被收合。
   - 做法：選單開著時在下面墊一層透明 scrim（手機用 bg-ink/10），點 scrim 只會關選單。
   - 工作量：S
4. **鍵盤出現時，分頁列蓋住輸入框**
   - 位置：`TabBar.vue`、`index.html` viewport、SpotActions 的新清單／新行程名稱、FindEditor。
   - 原因：模擬鍵盤時，「新行程名稱」下半被分頁列蓋住，「新增」被切掉。
   - 做法：
     - 觸控裝置上，input 或 textarea 聚焦時隱藏 TabBar，輸入框 `scrollIntoView({block:'nearest'})`。
     - viewport 加 `interactive-widget=resizes-content`，讓 dvh 的對話框跟著鍵盤縮。
     - 要在 Android 與 iPhone 實機各確認一次。
   - 工作量：S
5. **頁面程式載入失敗時沒有任何反應（離線，或部署後舊分頁）**
   - 位置：`services/viewTransition.ts` 的 `router.onError`。
   - 原因：離線時點「行程」完全沒有反應；直接 push 會丟出 `Failed to fetch dynamically imported module`。
   - 做法：
     - 在線上：重新載入一次目標網址，用 sessionStorage 防止一直重載。
     - 離線：用 AppUpdate 樣式顯示一行「離線中，無法開啟這一頁」。
   - 工作量：S
6. **未登入時，「行程」「紀錄」頁只有一句話**
   - 位置：`TripsView.vue`、`LogView.vue`。
   - 原因：唯一的「登入」在 header 右上角。
   - 做法：句子下面放 Primary「登入」鈕，文案不變。
   - 工作量：S
7. **橫向瀏海：內容與地圖控制項被瀏海蓋住**
   - 位置：`App.vue <main>`、地圖浮動面板與控制欄。
   - 原因：用 CDP 設安全區（左右 47）時，只有 header 有內縮；縮放鈕落在瀏海內。
   - 做法：
     - `<main>` 加左右 `env(safe-area-inset-*)`。
     - 地圖本身鋪到瀏海下面，浮動面板與控制欄加 inset。
     - 768 以上沒有分頁列時，補上底部安全區。
   - 工作量：S
8. **header 的「離線」標記在 360 寬折成「離／線」**
   - 位置：`AppHeader.vue`。
   - 做法：加 `shrink-0 whitespace-nowrap`；380 以下隱藏 HITOMEGURI 那一行。
   - 工作量：S
9. **iOS 的搜尋可能不會叫出鍵盤（實機確認）**
   - 位置：`SearchBox.vue`、`AppHeader.vue`。
   - 原因：focus 寫在 onMounted，不在點擊的同一個事件裡。
   - 做法：搜尋列改成 v-show，在放大鏡的 click 裡直接 `input.focus()`。
   - 工作量：S

### 探索（/、/map/:pref）

10. **選取的景點、「在地圖上看」的祭典釘落在 sheet 或清單底下**
    - 位置：`MapView.vue` fit()／flyTo()、`ExploreView.vue`。
    - 原因：鏡頭只扣掉桌機的左欄（insetLeft，手機是 0）。390 時選取的點在 y≈451，sheet 從 281 開始；祭典釘的中心點到的是清單列。進入縣時，縣的北半部在清單底下。
    - 做法：
      - MapView 多收 `insets {top, bottom}`。ExploreView 用 ResizeObserver 量上方清單卡的底緣和 sheet 高度。
      - padding 與 offset 都加上這兩個值。
      - 有 `?at=` 祭典釘時，比照開 sheet 收起清單，底部改成一張小紙卡：祭典名、「‹ 祭典」回 `/region/:pref#festivals`、關閉。
    - 工作量：S（鏡頭）＋S（祭典卡）
11. **景點 sheet 的收藏、去過、清單、行程要先捲 418px 才看得到**
    - 位置：`SpotPanel.vue`、`SpotActions.vue`。
    - 原因：sheet 高 506，內容高 924–1219，動作區在最底部。
    - 做法：
      - 手機上把動作區改成貼在 sheet 底部的工作列：`sticky bottom-0 border-t border-line bg-paper`，四顆 44px，圖示在上、text-label 在下。
      - 「在 Google Maps 開啟」移到資訊列。
      - 擴充包點的 sheet 改成依內容高度（`max-h-[60dvh]`）。
      - 拖曳與三段高度放在第二階段。
    - 工作量：M
12. **擴充包在手機上會被打開，但看不到、也關不掉**
    - 位置：`ExploreView.vue` 擴充包列（max-lg:hidden）、PackList（`desktop &&`）。
    - 原因：從 sheet 點「附近的寶可夢」後，URL 留著 `?pack=pokemon`。地圖變成擴充包模式，畫面上卻沒有任何狀態，也沒有地方可以關。
    - 做法：至少在海報條下面放一顆「目前的擴充包」chip，點了關閉；擴充包開著時，上方清單換成 PackList（拿掉 `desktop &&`）。完整的 chip 軌道見決定事項 C。
    - 工作量：S（最小版）
13. **「附近的…」第一次點只會開啟擴充包，不會打開那個點（桌機也有）**
    - 位置：`ExploreView.vue` select() 與 `watch(explore.pack)`。
    - 原因：兩組實測都重現。store 的 watcher 用舊的 route.query 做 replace，把 spot 蓋掉了。
    - 做法：pack 與 spot 合成一次 replace；watcher 在 URL 已經相同時跳過。
    - 工作量：S
14. **返回手勢直接離開地圖頁，不會先關 sheet**
    - 位置：`ExploreView.vue` select()／closeSpot()。
    - 原因：選取景點用 replace，所以從首頁點進縣、開景點後按返回，會回到全國地圖。
    - 做法：
      - 手機上從「沒有選取」變成「有選取」時用 push，之後換景點仍用 replace。
      - 搜尋列與帳號選單在手機上開啟時也 push 一筆，popstate 時關閉。
      - 原生 `<dialog>`（CardViewer、FindGallery）在 Android Chrome 會自己處理返回鍵，不另外做。iOS 的邊緣滑動要實機確認後再決定。
    - 工作量：M
15. **深度探索、直飛航線、縣的期間限定在 1024 以下沒有入口**
    - 位置：`ExploreView.vue` 深度探索連結、RegionTag、期間限定卡（都是 max-lg:hidden）；`UserMenu.vue`（/limited 只在登入後的選單裡）。
    - 原因：`a[href="/region/kyoto"]` 在 390 與 820 都是 display:none。未登入的手機使用者到不了連鎖店搜尋（A6）與航線（A7）。TODO.md 已知限制有列。
    - 做法：拆開海報條。
      - 左端是 44px 的「‹ 全國」鈕。
      - 中間是假名、縣名、羅馬拼音，不能點，所以拿掉跟畫面文字不符的 aria-label「切換地區」。
      - 右端是「深度探索 ›」，min-h-tap，前面一條 on-region/25 分隔線，和桌機 RegionTag 的規則相同。
      - 深度探索頁的海報補上航線一列，期間限定已經在那一頁。
    - 工作量：M
16. **清單捲動區沒有 overscroll-contain**
    - 位置：`RegionLists.vue`、`HomeSidebar.vue`、`PackList.vue`。
    - 原因：在清單頂端往下拉，會傳到頁面變成重新整理。
    - 做法：加 `overscroll-contain`。這是內層捲動區，不必等整頁的決定。
    - 工作量：S
17. **地圖出處一開始是展開的**
    - 位置：`MapView.vue`。
    - 原因：390 時首頁、縣頁、行程、紀錄的地圖底部有 2 行，約 44–75px；/log 260px 的小地圖被蓋掉三分之一。
    - 做法：手機在 load 後拿掉 `maplibregl-compact-show`，只留 ⓘ，授權照舊。
    - 工作量：S

### 深度探索（/region/:pref）

18. **段落列在頁頂時亮的是「期間限定」**
    - 位置：`composables/scrollSpy.ts`、`RegionView.vue`。
    - 原因：資料載入前頁面很短，被當成已經捲到底。
    - 做法：內容高度變了就 refresh；「在底部就亮最後一段」的規則只在 scrollTop > 0 時才用。
    - 工作量：S

### 行程

19. **離線時行程改不了，失敗訊息在清單最底看不到**

    - 原因：離線時按「往前」，15 秒後才有 `trips.error`，而且在待排的下面。
    - 做法：採決定事項 G 的 A。
      - 離線時把「移到」「⋯」「刪除這天」「加一天」設成 disabled。
      - 標題下放一行「離線中・行程不能修改」，用 header 離線標記的樣式。
      - 失敗訊息也改放這一行。
    - 工作量：S

### 紀錄

20. **批次補日期時，點列會離開頁面，選取與日期都會丟掉**
    - 位置：`MarkedSpotList.vue`。
    - 原因：只有左邊 44px 的勾選欄會切換，其餘約 300px 是連結。
    - 做法：`selected` 有值時，整列改成 `<label>`，選中的列用 bg-region-tint。
    - 工作量：S
21. **經縣值的等級選單在畫面下半會被分頁列蓋住，或讓頁面自己跳動**
    - 位置：`KeikenView.vue` pick() 與 focus。
    - 原因：點鹿兒島時選單到 y=845，分頁列從 787 開始，「未踏」「取消」看不到；另一次 focus() 讓整頁自己捲動。
    - 做法：先把選單位置限制在可見區內，focus 加 `{preventScroll:true}`。手機改成貼在分頁列上方的條狀選單，列在第二階段。
    - 工作量：S

### 收集

22. **橫向時卡片檢視、開卡包、新卡亮相把卡片切掉，按鈕在畫面外**
    - 位置：`CardViewer.vue`、`PackOpening.vue`、`CardReveal.vue`。
    - 原因：844×390 時卡片在 y=-119，按鈕在 y=470，而且不能捲。
    - 做法：卡片寬也依高度算，比照 TenPull 的 `--cw`：`min(320px, (100dvh − 控制列) × 5/7)`。`max-height: 500px` 時卡片在左，按鈕排成一欄放右側，像切符的副券。
    - 工作量：M
23. **規則對話框捲下去後，「關閉」就不見了**
    - 位置：`RulesDialog.vue`。
    - 原因：卡片、旅人、成就三份規則都有 1000–1400px 的內容，header 跟著捲走。
    - 做法：header 改成 `sticky top-0 bg-paper`，「關閉」用 min-h-tap。
    - 工作量：S
24. **點收集冊地圖上的縣，停在別的縣（桌機也有）**
    - 位置：`CardsView.vue` jumpTo()、`.deal` 的 content-visibility。
    - 原因：點京都停在大阪。smooth scroll 用的是估計高度 360，實際列高約 327，捲動途中目標一直在移動。
    - 做法：跳轉前把目標以上的段落設成 `content-visibility: visible`，或先瞬間跳到位置，下一幀再校正。
    - 工作量：S
25. **先翻到背面再按「抽一張」，新卡停在背面**
    - 位置：`CardViewer.vue` 的 variants watcher。
    - 做法：換到新抽的樣式時設 `flipped = false`。
    - 工作量：S

## 3. 第二階段（好用：單手、少捲動、手感）

### 全站

1. **觸控目標 44px**
   - 範圍：
     - 返回連結（44×20）、底線索引（類型、月份、節氣站 21–26×24）
     - SectionNav 32、h-9 列狀按鈕
     - 轉乘路線 18、「全部」、來源連結 14–18
     - 經縣值等級鈕 38×32（改成無間隙的分段條）
     - 卡片檢視的樣式 chip 32、篩選 chip 36、AppUpdate 36、共編面板 36
   - 做法：照決定事項 B，只加 `pointer-coarse:`。相鄰的底線索引用實際內距（py-2.5），不用 ::after，否則會重疊、點錯。MapLibre 控制項不在範圍內，使用者已說 44px 太大。
   - 工作量：M（分散在約 25 個元件，每處都是 S）
2. **分頁記住上次的位置，點目前的分頁回到頂端**
   - 位置：`TabBar.vue`。
   - 原因：行程 → 探索 → 行程，每次都要重找縣或行程。在深度探索頁點「探索」會回到全國。
   - 做法：照決定事項 E。
   - 工作量：M
3. **效能**
   - 關 sheet 時不要重建清單：RegionLists、PackList 用 v-show。4x 降速下 1125ms 會降到不必重建，捲動位置也會保留。（S）
   - 類型篩選切回「不限」要 2.9–3.9 秒：先畫按鈕狀態，地圖用 filter 或 feature-state，不整份 setData。（M）
   - 收集冊篩選 835ms：保留元素，用 hidden 切換。（M）
   - 深度探索的月份與特色群組加 content-visibility，特色 bundle（約 1.8MB）改成分縣。（S–M）
   - /log 小地圖在進入可見範圍或閒置時才建立。（S）

## 6. 不建議做的

- **把縮放鈕或其他 MapLibre 控制項放大到 44px**：使用者已經說太大。觸控目標的整理不包含地圖控制項。
- **在手機上恢復散步的旅人或「立體」**，或把旅人的提示（有新成就、還差哪幾縣…）改成手機上的文字列：使用者已經決定在手機隱藏。另外加說明句也違反 §6a。成就的「還沒去」與入口卡的 NEW 已經足夠。
- **用 ::after 擴大相鄰底線索引的點擊區**：相鄰的區域會重疊約 9px，反而更容易點錯，要用實際內距。
- **讓整個 sheet 的內容都可以拖**：會和 sheet 內的捲動衝突，只綁在把手與名稱帶上。
- **手勢教學、第一次使用的提示卡，或「往上拉看更多」這類說明**：§6a 不要 onboarding 說明卡。用把手的外觀與收合段露出名稱，讓人自己看得懂。
- **離線時讓行程寫入待同步**（在沒有設計衝突處理之前）：共編的兩個人可能互相覆蓋，比「不能改」更糟。
- **另外設計一套平板雙欄版面**：手機版面還沒完成，先統一用手機版面（A2）。
- **自己做下拉重新整理的動畫或手勢**：資料同步與版本更新已經由 Firestore 與 AppUpdate 處理，不需要。
- **在第一階段修扭蛋的黑色方塊**：可能是 headless 繪圖的假象，先在實機確認。
- **橫向時每一頁都重新排版**：只處理會掉出畫面或不能用的地方（卡片浮層、帳號選單、地圖頁、經縣值），其他頁可以直接捲動閱讀。
